# Graphics / images / brushes / text / SkiaSharp audit — maui-sailfish (feature/fixes) vs .NET MAUI 11 RC1

Static analysis only (no build, no device). Reference: Microsoft.Maui.Graphics / Microsoft.Maui / Microsoft.Maui.Controls 11.0.0-rc.1.26451.6 (netstandard2.0 / net11.0 builds, Android build consulted where noted). Paths are repo-relative unless stated.

## Summary

- **ICanvas is fully implemented syntactically** (`QtHostCanvasRecorder` has every member of the RC1 interface, nothing throws) and replayed in a Qt 5.6 `Canvas` Context2D. Lossy by design: `DrawImage` is a no-op (`QtHostCanvasRecorder.cs:164-165`, `GraphicsView.qml:206-209`), `SubtractFromClip` is dropped (`:117-118`, qml `:147-150`), `IAttributedText` is flattened to plain text (`:179-180`), `Antialias` is recorded but never applied (qml `:96`), only 16 of 28 `BlendMode` values map (qml `:296-300`), `ImagePaint`/`PatternPaint` degrade to `ForegroundColor` (`QtHostShapes.cs:162-163`), text layout is a greedy JS word-wrap with `1.2 × fontSize` line height (qml `:375-418`).
- **Two correctness defects in the canvas text path:** (1) `DrawString(value,x,y,ha)` puts the text *top* at `y` (`GraphicsView.qml:362-370`), while MAUI's Android `PlatformCanvas` translates to `y − fontSize` (text top at `y − fontSize`, i.e. `y` ≈ baseline; decompiled `PlatformCanvas.DrawString(string,float,float)`), so canvas text sits one line too low vs Android; (2) `ICanvas.Font` passes the raw `IFont.Name` (a ConfigureFonts alias) to the Context2D font string (`QtHostCanvasRecorder.cs:83-87`, qml `:343-350`) without `QtHostFonts.Resolve`, while `GetStringSize` *does* resolve it (`QtHostTextMetrics.cs:39`) — measured with the app font, painted with Qt's fallback.
- **GraphicsView interaction callbacks are not wired at all:** no `StartInteraction/DragInteraction/EndInteraction/CancelInteraction` anywhere in `src/` (grep), `GraphicsView.qml` has no `MouseArea`/touch item, and `QtHostInput.cs` only dispatches Tap/Pan/Pointer gesture recognizers (`:69-82`). Hover is N/A on the phone, but press/drag/release are a real gap for GraphicsView-based chart/gauge libraries.
- **Image resolution is hard-coded and bypasses MAUI's `IImageSourceService` DI** (zero hits for `IImageSourceService`/`ImageSourceServiceProvider` in `src/`). MAUI registers the four default services (`MauiAppBuilder` ctor → `ConfigureImageSources()`), but the Sailfish Image/Button/Slider/Page paths all call `QtHostImages.Resolve` (`QtHostImages.cs:192-201`), whose only extension point is the Sailfish-specific synchronous `QtHostImageSources.Register(Func<ImageSource,string?>)` (`QtHostImageSources.cs:27-32`). A library's `services.AddService<GravatarImageSource, GravatarImageSourceService>()` is silently ignored. Architectural gap; design sketched below.
- **Image loading itself is in good shape:** File (resource probe + `maui-resized.txt` scale rule), Uri (Qt disk cache 64 MB with `CachingEnabled`/`CacheValidity` honoured via a stamped header + URL-fragment policy, stall watchdog, 2 retries), Stream (async copy to cache file), FontImageSource (glyph PNG via QPainter, cached by SHA1 key). Gaps: stream cache files are never deleted (`QtHostImages.cs:292`, no cleanup anywhere), a GIF from a `StreamImageSource` never animates (the `.img` extension defeats the `.gif` regex, `Image.qml:50`), `Image.IsLoading` is never set (no `IsLoading`/`UpdateIsLoading` hits), unsized or `Aspect.Center` images decode at full size (memory risk), `FontAutoScalingEnabled` ignored.
- **No Sailfish `IImage` exists.** On this TFM `Microsoft.Maui.Graphics.Platform.PlatformImage.FromStream` compiles and returns a `PlatformImage` that only parses PNG/JPEG headers; its `Draw`, `Downsize`, `Resize` throw `PlatformNotSupportedException` and `Save` works only in the original format (decompiled netstandard build). `Screenshot.CaptureAsync` returns a PNG-file-backed `IScreenshotResult` (`SailfishShareAndPickers.cs:421-460`) with no `IImage` bridge.
- **Brushes:** gradients work on Shape Fill/Stroke, BoxView, Border Background/Stroke (Canvas or QtGraphicalEffects); on every other `Background` (layouts, Page, Label, Button, Entry…) a gradient brush reduces to *nothing* (`QtHostPaint.Solid` returns null → `BackgroundColor` fallback, `QtHostPaint.cs:11-14`). `Shadow` and `Clip` work on every view through a per-view `layer.effect` (OpacityMask + DropShadow, FBO per view, `MauiLayerEffect.qml`) — correct but a per-view GPU layer; `Shadow.Brush` must be a `SolidColorBrush` (`QtHostVisualState.cs:233`).
- **Fonts/text:** ConfigureFonts → `QFontDatabase` done, embedded fonts extracted to cache; FormattedText → Qt RichText HTML spans (color/bold/italic/family/size/decorations) but no per-span `BackgroundColor`, `CharacterSpacing`, `LineHeight`, `TextTransform` or span gestures (`AdapterSnapshots.Label.cs:95-125`); multi-font spans are *measured* with the first span's font only (`SailfishMeasure.cs:111-135`); `FontAutoScalingEnabled` not mapped anywhere; `MiddleTruncation/HeadTruncation` force single-line (`AdapterSnapshots.Label.cs:69-82`).
- **SkiaSharp package** is complete for the raster path (SKCanvasView 1:1 pixels, coalesced invalidate, touch with synchronous `Handled`, SKGLView emulated on raster with `GRContext = null`, SK*ImageSource → PNG). Charts were empty in ported apps because (a) before this package SkiaSharp's plain-net handlers threw → empty container (now fixed: Microcharts/LiveCharts draw, `docs/skiasharp-plan.md:48-50`), (b) Syncfusion charts are `IDrawable`s whose text measurer throws on plain .NET (`docs/porting-existing-apps.md:304-307`), (c) SkiaSharp 2.88 apps are unsupported, (d) LiveCharts' plain-net input is a stub → no touch.
- **Performance footnotes:** every GraphicsView/DrawnView drawable is re-recorded on every reconcile pass (`SailfishSnapshotHandler.cs:123` → `QtHostPageRenderer.Walk.cs:266`; heartbeat 2 s, `QtHostPageRenderer.cs:545`) in addition to `Invalidate` and property changes; a 4096-command cap silently truncates heavy drawables (`QtHostCanvasRecorder.cs:15,218-233`); each painted Canvas holds an FBO/GL context (`DrawnView.qml:5-7`, `QtHostShapes.cs:259-260`).

## Image pipeline findings

### Resolution chain (hard-coded)
`QtHostImages.Resolve` (`QtHostImages.cs:192-201`): `FileImageSource` → `FileUrl`; `UriImageSource` file:// → path; http(s) → URL + `#maui-cache=N` fragment; `FontImageSource` → `GlyphUrl`; `StreamImageSource` → `StreamUrl`; anything else → `QtHostImageSources.Resolve` (registered `Func<ImageSource,string?>` resolvers, first non-null wins, `QtHostImageSources.cs:37-52`). Consumers: Image/ImageButton (`SailfishDrawingHandlers.cs:36-40`), Button icon (`AdapterSnapshots.Button.cs:43`), Slider thumb (`AdapterSnapshots.Values.cs:43`), Page background (`QtHostPageRenderer.cs:990`), measure (`SailfishMeasure.cs:376`, `:162-165`).

### `IImageSourceService` architecture gap (confirmed)
- MAUI side: `MauiAppBuilder(useDefaults)` calls `ConfigureFonts()` and `ConfigureImageSources()` (decompiled `MauiAppBuilder` ctor lines 153-154). `ConfigureImageSources()` registers `FileImageSourceService`, `FontImageSourceService(IFontManager)`, `StreamImageSourceService`, `UriImageSourceService` via `IImageSourceServiceCollection.AddService<T,…>` and the singleton `IImageSourceServiceProvider` (`ImageSourceServiceProvider.GetImageSourceService(Type)` → `ImageSourceToImageSourceServiceTypeMapping.FindImageSourceServiceType` → walks the source's interfaces to `IImageSourceService<TInterface>`). On the **net11.0 (non-platform) build** `IImageSourceService` and `IImageSourceService<T>` are *empty marker interfaces* and `FileImageSourceService` etc. have no load method; only the Android build declares `Task<IImageSourceServiceResult<Drawable>?> GetDrawableAsync(IImageSource, Context, CancellationToken)` and `LoadDrawableAsync(IImageSource, ImageView, …)` (decompiled Android `IImageSourceService`).
- Android flow (reference): `ImageSourcePartLoader.UpdateImageSourceAsync()` → `SourceManager.BeginLoad()` (cancels the previous load) → `handler.GetRequiredService<IImageSourceServiceProvider>()` → `imageSourcePart.UpdateSourceAsync(view, provider, Setter.SetImageSource, token)` (looks up `provider.GetImageSourceService(source.GetType())`, awaits `LoadDrawableAsync`) → `SourceManager.CompleteLoad(result)` (holds the `IDisposable` result; `IsResolutionDependent`) — decompiled Android `ImageSourcePartLoader`. `UpdateIsLoading(true/false)` is raised around it on `IImageSourcePartEvents`.
- Sailfish side: nothing consults `IImageSourceServiceProvider` (grep zero hits in `src/` and `docs/`). `Hosting/AppHostBuilderExtensions.cs` registers no image services (`:31-59`). Consequences: (1) a library-registered `IImageSourceService<TCustom>` (CommunityToolkit `GravatarImageSource`, FFImageLoading, SkiaSharp's own `SKImageSourceService` from `UseSkiaSharp()`) is ignored — SkiaSharp's sources work only because `SailfishSkiaSharp.Register` adds a Sailfish resolver (`SailfishSkiaSharp.cs:23`, `SkiaImageSources.cs:28-36`); (2) no cancellation of in-flight loads, no `IsLoading`, no async contract — `QtHostImageSources` resolvers must be synchronous on the Qt thread (`QtHostImageSources.cs:9`); (3) a custom `ImageSource` that *also* implements `IStreamImageSource` (Gravatar does) is not recognised either, because the switch matches concrete Controls types, not the Core interfaces (`QtHostImages.cs:194-198`).
- A Sailfish-shaped design: define `ISailfishImageSourceService : IImageSourceService` with `Task<IImageSourceServiceResult<string>?> GetUrlAsync(IImageSource source, CancellationToken ct)` (value = a `file://`/`http(s)://` URL Qt can load, `ImageSourceServiceResult` holds the delete action for temp files); register the four defaults through `builder.ConfigureImageSources(s => s.AddService<IFileImageSource, SailfishFileImageSourceService>() …)` in `SetupSailfishDefaults` so the mapping table knows them; make `QtHostImages.Resolve` first try `MauiContext.Services.GetRequiredService<IImageSourceServiceProvider>().GetImageSourceService(source.GetType())`, and when the service is Sailfish-shaped run it through the existing pending/`WhenReady` machinery used for streams (`QtHostImages.cs:247-313`), reporting `UpdateIsLoading`; keep `QtHostImageSources.Register` as a thin adapter that wraps a `Func` into such a service. `ImageSourceServiceResultManager` (internal in Core, decompiled) shows the token/dispose discipline to mirror. Alternative value type: a texture/QImage handle — not available through the current shim ABI (sources are URLs; `Image.qml:6`).

### FileImageSource
- Lookup: as given → `baseDir/<file>` → `baseDir/images/<name>` → `baseDir/Resources/Images/<name>` → Sailfish theme icon dirs for `icon-*`/`image-*` names (`QtHostImages.cs:323-351`). Absolute paths work (`:325-326`). **MauiAsset** (`Resources/Raw`) is not in the candidate list — only if the file lands next to the binary (unverified where the build task copies assets).
- Intrinsic size: resizetizer rasters listed in `images/maui-resized.txt` count as 4× (`:165-173`), unresized copies 1 dp/px, other files px ÷ density (`:117-129`); headers read without decoding (`ImageHeader.cs`, PNG/GIF/BMP/WebP/JPEG). Tested (`ImageMeasureTests.cs:78-131`).
- Unresolvable source → no host at all (`SailfishDrawingHandlers.cs:36-37`), no error event (MAUI has none either; one log line per URL `:56-57`).

### UriImageSource
- Qt's `QNetworkAccessManager` loads it (`Image.qml:149`). Shim installs `QNetworkDiskCache` at `~/.cache/<org>/<app>/qml-http`, 64 MB default (`MAUI_SAILFISH_HTTP_CACHE_MB`), every entry stamped with `X-Maui-Cached-At` (`host_core.cpp:823-835`, `:935-949`).
- `CachingEnabled`/`CacheValidity` honoured: `#maui-cache=0` → `AlwaysNetwork` + no store; `#maui-cache=N` → `PreferCache` if younger than N s else `AlwaysNetwork` (`QtHostImages.cs:208-214`, `host_core.cpp:870-914`). An app's own fragment disables the policy (`:210-211`). Default (no fragment) `PreferCache`.
- No custom headers / no shared `HttpClient` (Android uses Glide, iOS NSUrlSession — also not MAUI's `HttpClient`, so parity is fine). Stall watchdog aborts a reply with no data for 20 s (`host_core.cpp:838-864`); `Image.qml:87-97,159-163` retries twice (1 s, 3 s) then fires `image-failed`.
- Natural size reported once loaded for layout (`Image.qml:81-85`, `QtHostImages.cs:150-157`, `SailfishDrawingHandlers.cs:47-55`, test `ImageMeasureTests.cs:161-176`).

### StreamImageSource
- `Stream(CancellationToken.None)` awaited, copied to `cache/streams/<guid>.img`; host appears on the next reconcile (`QtHostImages.cs:272-313`). **No cleanup:** files are never deleted (not on source GC, not on startup); `ConditionalWeakTable` only forgets the path. Disk grows with every stream source an app creates (photo pickers, generated thumbnails). Cancellation token is `None`.
- `.img` extension → `__gif` regex false (`Image.qml:50`) → an animated GIF from a stream shows its first frame only, `IsAnimationPlaying` ignored.

### FontImageSource
- Rendered by `QPainter::drawText` into an ARGB PNG at `Size × Density` px (default size 30), centred in a square ≥ px (`host_text.cpp:29-57`); colour defaults to white (`QtHostImages.cs:230`; Android also defaults to white). Family resolved through `QtHostFonts.Resolve` (`:228`). Cached in memory by key and on disk by SHA1 in `cache/glyphs` (`:231-241`). Requires Qt thread and running host, else `null` (`:226`) — a glyph resolved off-thread yields no host until the next reconcile. `FontAutoScalingEnabled` ignored (property not read). Device-verified (F3 `:1166`, `:1177`).

### `IImage` / `PlatformImage` / Screenshot
- `Microsoft.Maui.Graphics.Platform.PlatformImage` (netstandard build, the one a `net11.0-sailfish` app binds): `FromStream` **exists** and returns `new PlatformImage(bytes, format)` which only parses PNG/JPEG dimensions; `Draw(ICanvas)`, `Downsize(…)`, `Resize(…)` throw `PlatformNotSupportedException`; `Save` writes bytes only when `format == originalFormat`, else `NotImplementedException`; `ToPlatformImage()` returns itself (decompiled). So a library calling `PlatformImage.FromStream(...)` then `canvas.DrawImage(img, …)` gets: no exception from `DrawImage` on Sailfish (recorder skips), but any `image.Draw(canvas, rect)` throws.
- No Sailfish `IImage` implementation (no QImage- or Skia-backed type in `src/Linux.SailfishOS` or `src/Linux.SailfishOS.SkiaSharp`; grep). `Screenshot.CaptureAsync` → `grabWindow` PNG file → `IScreenshotResult` with `OpenReadAsync`/`CopyToAsync` PNG only (`SailfishShareAndPickers.cs:421-460`; `:455` rejects other formats). No `IScreenshotResult → IImage` path.
- Gap for chart libraries: any `IDrawable` drawing bitmaps (markers, legend icons, watermarks) renders nothing; libraries that rasterise to `IImage` for export (`Save`) cannot on this platform. SkiaSharp-based libraries are unaffected (they use `SKImage`).

## SkiaSharp findings

- **Registration:** `SailfishSkiaSharp.Register()` replaces SkiaSharp's plain-net `SKCanvasViewHandler`/`SKGLViewHandler` (which throw in `CreatePlatformView`) and adds the `SK*ImageSource` resolver (`SailfishSkiaSharp.cs:16-24`); invoked from a `buildTransitive` registrar attribute so `UseSkiaSharp()` stays unchanged (`docs/skiasharp-plan.md:92-95`; `custom-controls.md:235-239`). Subclasses (library chart views) resolve to it (test `SKCanvasViewHandlerTests.cs:56`).
- **SKCanvasView (raster):** RGBA8888-premul `SKBitmap` the size of the view in device px (Android `ToPixels` rounding, `SkiaSurfaceRenderer.cs:92-110`), reused between paints, painted once in the next frame per `InvalidateSurface` (`:120-125`, `QtHostSurface.cs:134-141`), `Info`/`RawInfo`/`IgnorePixelScaling` as Android (`:149-165`), committed via `QtHostSurface.Commit` → shim staging copy → `glTexSubImage2D` into a persistent texture on the render thread, tiled above `GL_MAX_TEXTURE_SIZE` (`QtHostSurface.cs:9-14`; `host_surface.cpp:12`, `:35-66`, `:271-305`). Hidden/zero-size → pixels freed (`:112-118`, `:129-141`). Touch: synchronous `Handled` on the first press decides gesture ownership, pointer ids Android-style, Flickable drag → `Cancelled` (`QtHostSurface.cs:66-129`; `SkiaSurfaceRenderer.cs:182-252`). Measured on device: 1:1 pixels, ~88 fps for a 993×764 canvas, 1.1 ms commit + 2.1 ms upload (`skiasharp-plan.md:65-69`). This is the one sanctioned per-paint CPU upload in `architecture.md:61-66`.
- **SKGLView:** same raster path; `GRContext` null, `BackendRenderTarget` a dummy `GL_RGBA8` descriptor (`SailfishSKGLViewHandler.cs:10-16`, `:40-44`); `HasRenderLoop` repaints every frame (`:73-75`, `SkiaSurfaceRenderer.cs:38-48`, `:169-170`). Limit: no GPU path — `libSkiaSharp.so` (Linux glibc build) is GLX-only, Sailfish is EGL/GLES (`skiasharp-plan.md:39-41`); a real `GRContext` would need `GRGlInterface.CreateGles` on Qt's context + a `QQuickFramebufferObject` primitive (`:137-139`). Apps calling `e.Surface.Canvas` only (LiveCharts `UseGPU`) work.
- **SK*ImageSource:** `SKImage`/`SKBitmap`/`SKPixmap`/`SKPicture(Dimensions)` encoded once to a PNG in `cache/skia` and re-encoded when the object/dimensions change; the previous file is deleted (`SkiaImageSources.cs:28-67`). Picture rasterised manually because `SKImage.FromPicture` segfaults in 3.116 (`:38`). Tests `SKGLViewAndImageSourceTests.cs:137-162`.
- **Mapper compat:** apps extending SkiaSharp's own `SKCanvasViewHandler.SKCanvasViewMapper` get nothing — extensions must target `SailfishSKCanvasViewHandler.Mapper` (`SailfishSKCanvasViewHandler.cs:17-20`; `skiasharp-plan.md:90`).
- **Why charts were empty (docs/porting-existing-apps.md):** rows at `:11-14` predate the package — SkiaSharp views fell to an empty container (`:200-201`, `skiasharp-plan.md:42-43`). After `bc63d1e`: Profitocracy LiveCharts and WeightTracker Microcharts draw (`skiasharp-plan.md:48-50`). Still empty: **Syncfusion charts** — `IDrawable`s whose plain-.NET text measurer throws inside `Draw` (`porting-existing-apps.md:148-151`, `:304-307`; `SailfishDrawnViewHandler.cs:7-14`, `QtHostGraphics.cs:40-47` log once and keep the partial recording); **MoneyFox** (LiveCharts rc2 on SkiaSharp 2.88, unsupported `:132`, `skiasharp-plan.md:32-34`); and **GraphicsView-based** charts render but take no touch (interaction gap above). LiveCharts touch is a stub in its own plain-net asset (`:133-134`).
- **DrawnView fallback (non-Skia libraries):** a library view that is `IDrawable` + `IContentView/ILayout` gets `SailfishDrawnViewHandler` (`QtHostLayout.cs:28-32`) → same recorder/replay under its children (`DrawnView.qml:24-34`); the library's own invalidate never reaches it, so animations show end states only (`porting-existing-apps.md:196-197`).
