# Collections audit — maui-sailfish (feature/fixes) vs .NET MAUI 11 RC1

Static analysis only (no build, no device). Reference: `Microsoft.Maui.Controls.dll` 11.0.0-rc.1.26451.6 decompiled with ilspycmd; line numbers below marked `maui11/…` refer to those decompiles, all other paths are repo-relative under `/Users/mer/Projects/maui-sailfish/`.

## Summary

- **Core CollectionView works and is device-proven.** Native virtualized `SilicaListView` (`qml/containers/ListView.qml:22`) with MAUI-owned row content, keyed incremental model diff (`ListView.qml:194-245`), grouping with header/footer templates (`QtHostListAdapter.Rows.cs:337-365`), vertical/horizontal linear and grid layouts (`QtHostListAdapter.cs:225-263`), Header/Footer/EmptyView slots (`QtHostListAdapter.Slots.cs`), Single/Multiple selection (`QtHostListAdapter.Input.cs`), `ScrollTo` incl. group index, `Scrolled`, `RemainingItemsThresholdReached` (`QtHostListAdapter.Scroll.cs`), RefreshView wrapping, row pool, per-row remeasure. Matrix legs `collection collection10 collection100 collection500 f3 containers` (`tools/cmd/matrix.sh:22,36-38`) and host tests (`tests/Linux.SailfishOS.Tests/Renderer/CollectionBridgeTests.cs`, `Renderer/HandlerFixTests.cs`, `RowLookupTests.cs`) cover it.
- **Blocker: `DataTemplateSelector` is not supported anywhere in the list path.** `QtHostCollectionBridge.CreateFromTemplate` calls `template.CreateContent()` directly (`QtHostCollectionBridge.cs:569`); MAUI 11 throws `InvalidOperationException("Cannot call CreateContent directly on a DataTemplateSelector")` (`maui11/ElementTemplate.cs:93-96`). The exception is swallowed (`:574-578`), the row view is null and 0 dp high, so a selector-driven CollectionView/CarouselView renders empty (also GroupHeader/GroupFooter/Header/Footer/EmptyView templates). No `SelectDataTemplate`/`SelectTemplate` call exists in `src/`.
- **Blocker for legacy apps: `ListView`, `TableView` and all `Cell` types have no handler and render blank.** `ListView : ItemsView<Cell> : View` (`maui11/ListView.cs:18`, `maui11/ItemsView_1.cs:9`) does not derive from `ItemsView`, so `Row<ItemsView, SailfishListViewHandler>` (`SailfishHandlersFactory.cs:246`) does not match and resolution falls to `SailfishContainerHandler` (`SailfishHandlersFactory.cs:198-201`, `SailfishLayoutHandlers.cs:177-197`), which only paints a background. Cells are never realized (`ListView._visualChildren` is filled only by `SetupContent`, `maui11/ListView.cs:624-637`, which a platform renderer drives). Not mentioned in `docs/porting-existing-apps.md`.
- **MAUI behaviours missing:** `ItemsUpdatingScrollMode` (no reference in `src/`; `samples/Linux.SailfishOS.Sample/Pages/CollectionAdvancedPage.xaml:19` sets `KeepLastItemInView` and gets nothing), `ItemSizingStrategy` (always MeasureAllItems — every item is templated *and* measured at build, `Rows.cs:201-204`), `SnapPointsType/SnapPointsAlignment` on CollectionView, `CanReorderItems/CanMixGroups/ReorderCompleted`, the VSM `Selected` state on item roots and the carousel `CurrentItem/NextItem/PreviousItem/DefaultItem` states (no `GoToState` in `src/`), `CarouselView.VisibleViews/IsDragging/IsScrolling/IsScrollAnimated`, `ScrollTo(animate:)` (Qt 5.6 `positionViewAtIndex` is immediate, `ListView.qml:300`), `ItemsViewScrolledEventArgs.Horizontal/VerticalDelta` (never set, `Scroll.cs:60-68`), runtime `Span`/`ItemSpacing` changes on the same layout object (no `ItemsLayout.PropertyChanged` subscription).
- **RefreshView UX decision:** pull = top overscroll past `Theme.itemSizeMedium` on the list/scroll/page flickable + a centred `BusyIndicator` while `IsRefreshing` (`ListView.qml:86,124-129,453-462`, `qml/lib/pullrefresh.js`). It arms **only when the page has no pulley**: any `ToolbarItems` or a Shell/FlyoutPage flyout disarms it silently (`QtHostPageRenderer.Layout.cs:640-650`), and no "Refresh" pulley entry is added instead. In a Shell app with a flyout, `RefreshView` never fires from a gesture.
- **Recycling semantics differ from RecyclerView/UICollectionView:** one MAUI view per item lives as long as the item is in the source (`Rows.cs:201`, reused by identity `:57-66`); views are never rebound to other items, so `OnBindingContextChanged` runs once and template-local state persists per item; memory is O(N) MAUI views. The pool recycles QML hosts only, for rows whose adapters are all in `PoolableUris` (`RowPool.cs:23-26`) — rows containing an Entry, SwipeView, nested list or ScrollView are destroyed and recreated on every scroll-in.
- **Risk — unbounded CollectionView (StackLayout/ScrollView):** it measures to its full content extent (`SailfishMeasure.cs:350-363`), so every delegate is "in view"; materialization is capped at `MaxDelegates = 192` (`QtHostCollectionBridge.cs:27`, `Delegates.cs:197-201`) and rows past the cap stay blank. Whether the inner Qt ListView hands vertical drags to the outer flickable is unverified.
- **Architecture rule ("C# does not know Silica", `docs/architecture.md:53-56`):** no Silica class names are used in list C# logic; they appear only in comments (`Rows.cs:96`, `QtHostListAdapter.cs:389`, `FirstFrame.cs:24`). The one semantic shortcut is that a plain-string `EmptyView` on a vertical list is routed to a separate `mauiPlaceholderText` channel (`Rows.cs:98-101`) because C# knows the adapter shows it natively.
- **Parity tracking gap:** `docs/handler-parity.md` (100 %) excludes CollectionView/CarouselView — `HandlerParityTests.cs:25-53` lists no items handler — so the official `ItemsViewHandler`/`StructuredItemsViewHandler`/`ReorderableItemsViewHandler` mapper keys (`ItemsUpdatingScrollMode`, `EmptyViewTemplate`, `FlowDirection`, `ItemSizingStrategy`, `CanReorderItems`; `maui11/ItemsViewHandler_1.cs:86-97`, `StructuredItemsViewHandler.cs:156-164`, `ReorderableItemsViewHandler.cs:270`) are not counted.

## Architecture / performance notes

- **Row pool "same shape" rule vs DataTemplateSelector.** The pool keys on the pre-order adapter/parent shape (`RowPool.cs:50-68`), so once selectors work, rows of different templates pool separately and a template that produces varying shapes per item (conditional `IsVisible` does not change shape; conditional children do) simply pools less. No correctness risk there; the blocker is upstream in `CreateFromTemplate`.
- **MeasureAllItems cost on 500+ items.** `RebuildRows` templates (`CreateItemView`) and measures (`MeasureItemExtent`) every item synchronously on the Qt/UI thread (`Rows.cs:173-212`), and every MAUI view stays alive. The `collection500` leg passes, but no profiling numbers for it are recorded in `docs/profiling.md` (grep empty). Costs scale linearly with source size, not viewport size — the main divergence from RecyclerView/UICollectionView, and the reason `KeepLastItemInView`-style chat sources with thousands of messages will hurt. Mitigation path: honour `MeasureFirstItem`; estimate heights for off-screen rows and template lazily on `RequestMaterialize`.
- **First-frame hold** is off by default (`FirstFrame.cs:13-15`); the remaining startup cost is the rows' own template/measure burst above.
- **Selection visual.** The QML highlight sits under the content (`ListView.qml:354`); with opaque item templates (the Kitchen cards, the sample's `Border BackgroundColor="#1C1C28"`) the selected state is likely invisible on device — worth a screenshot check. Driving VSM `Selected` fixes both the visibility and parity.
- **CollectionView inside ScrollView.** Measures to full extent → defeats virtualization (as on Android) but additionally hits `MaxDelegates = 192` → blank rows past 192, and the nested-flick hand-off is unverified. Common in ported apps ("whole page in a ScrollView"); the porting doc does not mention it.
- **Scheduling.** List work runs on its own clock (`SchedulePending`, `QtHostCollectionBridge.cs:372-411`); a resync eval walks the QML tree 15×250 ms after every rebuild (`:525-526`, `Delegates.cs:23-63`) — a known leftover (C10 "replace the 15×250 ms resync sweep", `docs/architecture-plan.md:945-947`).
- **Dead code:** `View is IScrollViewController` in `Scroll.cs:58-59` can never be true for an `ItemsView`.
- **"C# does not know Silica" (architecture.md:53-56):** respected in the collections code — no `is <SilicaType>` checks, no Silica-specific ABI; Silica names only in comments (`Rows.cs:96`, `QtHostListAdapter.cs:389`, `FirstFrame.cs:24-25`). `SailfishMeasure.ThemeDp` evaluates `Theme.*` expressions from C# (`SailfishMeasure.cs:249-260`) but that is outside the list code and used for measures, not visuals.
- **Thread safety:** INCC from any thread → `QtHostRuntime.Post` (`QtHostListAdapter.cs:358-362`); `SelectionChanged` hops to the Qt thread (`:40-48`); `MarkRow`/`MarkSlot` hop too (`Rows.cs:275-278`, `Slots.cs:128-131`). Good.
- **Coverage gap:** the parity table (`docs/handler-parity.md`) and `HandlerParityTests.cs:25-53` omit the items handlers; adding `CollectionView`→`CollectionViewHandler` and `CarouselView`→`CarouselViewHandler` would surface `ItemsUpdatingScrollMode`, `ItemSizingStrategy`, `CanReorderItems`, `EmptyViewTemplate`, `FlowDirection` as tracked gaps.
